## Overview

Two related enhancements to the **Invoices** page (`/invoices`) of the VMBSO Customer Portal:

1. **Invoice Document Link** — Clicking an invoice opens its stored document (SharePoint).
2. **Point-Generating Line Breakdown** — Credited invoices expose an expandable section listing only the invoice lines that generated loyalty points, with product detail and per-line point amounts.

---

## Feature 1 — Invoice Document Link

### Background

Invoice records in Dataverse (`actum_invoice`) already contain a `actum_sharepointfileurl` field that is populated by the backend (Power Automate) when a document is stored. Currently the invoice cards in the portal display no link and are not clickable.

### Business Requirement

When a user views their invoice list, they must be able to access the stored invoice document directly from the portal.

### Business Rules

| Rule | Detail |
|------|--------|
| **Trigger** | User clicks the invoice card or a clearly labelled "View Document" action |
| **Condition** | The link/button is only rendered when `actum_sharepointfileurl` is non-null and non-empty |
| **Behaviour** | Opens the document URL in a new browser tab |
| **No URL** | When `actum_sharepointfileurl` is absent the card remains non-interactive (no broken link, no disabled button visible — the card simply has no click action) |
| **Status scope** | No restriction by invoice status — the link is shown whenever the URL field is populated. The backend controls when the URL is set |
| **Access control** | Same as existing Invoices page — no new permissions required |

### Data

- **Source field**: `actum_sharepointfileurl` on `actum_invoice`  
- **Already returned** by the existing invoice-fetch flow — no backend change required for this feature.

### Frontend Scope

- Make the invoice `<Paper>` card clickable, or add a discrete icon/button (e.g., open-in-new icon) that appears only when the URL is available.
- Open URL via `window.open(url, '_blank', 'noopener,noreferrer')`.
- No routing change — the card does not navigate within the SPA.

### Backend Scope

None — `actum_sharepointfileurl` is already returned. Confirm with Miroslav that the field is consistently populated for processed statuses (Extracted, Review, Credited).

## Feature 2 — Point-Generating Line Breakdown

### Background

When an invoice is **Credited** (`statuscode = 182980005`), the portal currently shows the total loyalty points granted (`actum_loaltypointsgranted` on the invoice header). It does not show which individual product lines drove those points.

Invoice lines are stored in the `actum_invoiceitem` table. Each line has an `actum_loaltypointsgranted` field that is **already populated** by the backend AI-extraction / approval process for qualifying products (confirmed: e.g. 12,000 pts on a single line). Lines that do **not** qualify for points have this field as `null`.

### Business Requirement

On a Credited invoice, users must be able to see which individual lines generated points and how many — so they can understand and verify their loyalty earnings.

### Business Rules

| Rule | Detail |
|------|--------|
| **Visibility** | The expandable section is only rendered for invoices with `statuscode = 182980005` (Credited) |
| **Line filter** | Only lines where `actum_loaltypointsgranted IS NOT NULL AND actum_loaltypointsgranted > 0` are shown |
| **Active lines only** | Query must filter `statecode = 0` on `actum_invoiceitem` to exclude deactivated records |
| **Empty state** | If a Credited invoice has no qualifying lines (all null/zero), show a message such as "No point-generating lines found" rather than an empty accordion |
| **Non-credited invoices** | No line breakdown section is shown — not even collapsed |
| **Access control** | Same as existing Invoices page |

### Data — `actum_invoiceitem` Table

| Field | Type | Purpose |
|-------|------|---------|
| `actum_invoiceitemid` | GUID | Primary key |
| `actum_name` | string | Product name (uppercase, as extracted) |
| `actum_normalizedname` | string | Normalized/lowercase product name (for internal use) |
| `actum_quantity` | number | Quantity on this line |
| `actum_unitprice` | number | Unit price |
| `actum_totalamount` | number | Line total (quantity × unit price) |
| `actum_loaltypointsgranted` | number \| null | Points generated by this line — **the key filter field** |
| `_actum_invoiceid_value` | GUID | Foreign key → `actum_invoice` |
| `_actum_brand_value` | GUID \| null | Brand lookup (may be null) |
| `statecode` | number | 0 = Active |

**FetchXML filter for qualifying lines:**
```xml
<fetch>
  <entity name="actum_invoiceitem">
    <attribute name="actum_invoiceitemid" />
    <attribute name="actum_name" />
    <attribute name="actum_quantity" />
    <attribute name="actum_unitprice" />
    <attribute name="actum_totalamount" />
    <attribute name="actum_loaltypointsgranted" />
    <attribute name="_actum_brand_value" />
    <filter>
      <condition attribute="_actum_invoiceid_value" operator="eq" value="@{invoiceId}" />
      <condition attribute="statecode" operator="eq" value="0" />
      <condition attribute="actum_loaltypointsgranted" operator="not-null" />
      <condition attribute="actum_loaltypointsgranted" operator="gt" value="0" />
    </filter>
  </entity>
</fetch>
```

### UI Behaviour

- Below the existing invoice header (name, date, status, total points), render a collapsible accordion / "expand" toggle.
- **Label** (collapsed): e.g. "View point details" or "Show earning lines (N lines)".
- **Expanded content**: A compact table or list showing per qualifying line:
  - Product name (`actum_name`)
  - Quantity (`actum_quantity`)
  - Line total (`actum_totalamount`, formatted as currency)
  - Points earned (`actum_loaltypointsgranted`, formatted as integer + "pts")
- **Total row**: Sum of `actum_loaltypointsgranted` across displayed lines should match the invoice-header `actum_loaltypointsgranted` (if not, surface as a data-quality warning — not a blocker for display).
- Accordion is collapsed by default; only one can be open at a time within the list (standard behaviour).

### Loading Strategy

The invoice list currently fetches all invoices at once. Point-line data must **not** be fetched upfront for all invoices — this would cause excessive API calls. Two acceptable approaches:

**Option A — On-demand (lazy load per invoice)**  
Fetch `actum_invoiceitem` lines only when the user expands the accordion for a specific invoice. Cache the result in component state to avoid re-fetching on collapse/expand.

**Option B — Batched on page load for Credited invoices only**  
After the invoice list loads, identify all Credited invoice IDs and issue a single batched FetchXML query filtering `_actum_invoiceid_value IN (id1, id2, ...)`. Store results mapped by invoice ID.

Option A is simpler to implement; Option B reduces perceived latency if users are likely to expand many invoices. The team should confirm which approach to implement in the estimate.

### Backend Scope

A new Power Automate flow (or an extension of the existing invoice flow) is needed to expose `actum_invoiceitem` data to the portal:

- **Input**: `invoiceId` (GUID)
- **Output**: Array of `actum_invoiceitem` records matching the filter above
- **Alternative**: If the portal has direct Web API access to `actum_invoiceitems`, this can be queried directly without a flow (confirm with Miroslav).
- **Note**: `actum_loaltypointsgranted` must be populated per line by the backend extraction/approval process **before** this feature is meaningful. Confirm current status of this backend step.

## Out of Scope

- Modifying the point-calculation logic (how points are assigned per line) — this is a separate backend concern.
- Showing lines that did **not** generate points (zero or null `actum_loaltypointsgranted`).
- Editing or re-submitting invoice lines from the portal.
- Pagination of invoice lines (assumed to be a manageable number per invoice).
